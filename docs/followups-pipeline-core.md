# Ascent pipeline-core — post-MVP follow-ups

From the final whole-branch review of `feat/mvp-pipeline-core` (all non-blocking; the MVP is merge-ready and all four safety properties hold). Ordered by recommended priority.

1. ~~**Sample engagement / `eng.urls` ignored.**~~ **Resolved (2026-10-31):** the DAST surface is now the union of recon over every host and every URL in the engagement (`src/stages/dast.rs`), so `urls` are no longer dropped when a host is set. Original problem: `run_pipeline` used recon-from-root whenever any host was set and ignored `eng.urls`, so a live run against OWASP Juice Shop (:3000) probed default ports via httpx and found nothing.
2. ~~**katana off-site endpoints can abort the scan (fail-closed).**~~ **Resolved (2026-10-31):** crawl results (and seeds) are filtered through the scope guard; out-of-scope URLs are dropped, counted in `run.json` (`dast.out_of_scope_dropped`) and never sent to a scanner, so one off-scope link no longer aborts the run. katana is also forced to `-fs fqdn` so it crawls only the exact hostnames it is given.
3. ~~**Crux spawned outside `ToolRunner`.**~~ **Resolved:** Crux is now linked as a library (`default-features = false`), so there is no Crux process to gate and no network code in the binary. If an LLM triager is ever enabled, it must go behind the data-governance gate (PRD section 4).
4. **Scope config hardening.** ~~Add `#[serde(deny_unknown_fields)]` to `Engagement` so a misspelled scope key (which silently shrinks scope — fails safe but quietly) becomes a loud error.~~ **Resolved (2026-10-31):** `Engagement` and its nested DAST structs reject unknown keys (exit 2). Still open: consider a scheme allow-list (http/https) and a resolved-IP re-check (DNS-rebinding) in `ToolRunner` for defense-in-depth.
5. **Validate hosts, URLs and CIDRs at engagement load.** An invalid entry (for example a URL with userinfo or a malformed CIDR) is silently ignored by the scope guard today, and a DAST run whose declared URLs are all invalid only fails later as INCOMPLETE (exit 3). Validating every entry with the guard's own parser in `load_engagement` would make it a configuration error (exit 2) before anything runs. Deferred from the DAST final fix wave (2026-10-31).
6. **Follow-redirect audit for katana and httpx.** nuclei runs with `-dr` and katana with `-dr`; httpx does not follow redirects by default and Ascent never passes `-fr`. Re-verify these defaults on every tool upgrade, and check whether katana's JavaScript parsing or headless mode can still fetch a redirect target outside `-fs fqdn`. Deferred from the DAST final fix wave (2026-10-31).
7. **nuclei egress beyond `@Host` (residual, 2026-10-31).** Templates whose raw-request `@Host:` names another host are excluded before the scan (`-et`), and every request nuclei sent is checked against the scope from its trace log (`-tlog`) after each pass (any off-scope request makes the run INCOMPLETE). Not pre-filtered: a template can still embed an absolute URL in a `path:` entry or in a raw request line (`GET https://other.example/ HTTP/1.1`), or build the host from an extractor at run time. Those requests ARE caught by the trace-log audit, but only after they were sent (with the auth header, when one is configured). Prevention would need a scope-enforcing forward proxy: run nuclei with `-proxy` pointing at a local proxy that refuses any CONNECT/request to a host the scope guard does not accept. Also open: the audit checks the host nuclei dialled, not the IP it resolved to (DNS rebinding; see item 4), and the template listing adds the time of one `nuclei -tl` call (about 20 s for ~11.5k http templates on the reference machine; caching the listing per templates version would remove it) to every live run.
8. **Cosmetic.** `audit.jsonl` path is printed even when no audit was written (dry-run / no findings); report fields are interpolated into markdown unescaped (local output); README "single static binary" is aspirational.

Deferred by design (per PRD/plan, not defects): time window not enforced; scope is lexical; triage runs Crux's offline `MockTriager`; no exploitation.

CI: `.github/workflows/ci.yml` checks out `Aldiharley/crux` next to Ascent for the path dependency. It goes green only once crux's Rust `main` is pushed (origin currently holds only the initial commit).
